# 首版开发需求

> 历史基线：本文件下方的“首版”决定描述 2026-09-25 的对话工具范围。2026-09-26 用户已批准新增独立面板，以下“当前面板需求”覆盖原“不提供面板/不共享连接”的范围限制，其他设备安全不变量继续有效。

## 当前面板需求（已确认）

2026-09-26 视觉反馈补充：现有 Tk 面板功能保留，但其原生 Windows 表单外观不满足用户期望。按 [网页风格面板开发计划](web-panel-plan.md) 已完成 HTML/CSS 视觉稿和独立 Windows 窗口宿主原型验证，后续逐阶段迁移相同的可见功能。pywebview/WebView2 目前仅为通过 UI-2 的技术方案，正式集成和打包仍待后续阶段；下列功能与设备安全要求不因换界面而放宽。

- Windows 独立小窗口，与 Codex 并排使用；通过开始菜单快捷方式或 Codex 对话中的打开面板工具进入。重复打开同一窗口，启动时不自动连接串口。
- 面板与 Codex MCP 工具共享同一个设备连接、连接状态和控制台缓冲；同一 Windows 用户一次只管理一个活动工作区和设备。连接期间不得静默切换工作区。
- 覆盖 DSH **可见面板**的工作区识别、选择、认领，机型/入口、策略、串口、状态、控制台、REPL、运行/中断/停止、下载及下载并运行。板载文件与 PID 图形编辑不属于本次面板范围；现有 MCP 工具保留。
- 默认 mock，真实桥仍按已有显式配置和门禁启用；不修改 DSH，也不自动抢占其串口。
- 面板自身发起的受策略保护操作由面板逐次显示目标和影响并取得人工确认。Codex 对话发起的真实需确认操作继续按现有 MCP 客户端确认规范 fail-closed；面板不替对话批准。
- 新面板不复用 DSH 关于实体电机已停的未证实文字。严格备份、校验和设备安全规范继续适用。

验收需区分无硬件 mock、假桥和经另行授权的实机试点；本轮计划批准不等于授权运行真实桥或操作实体设备。步骤及依赖见 [plan.md](plan.md)。

## 已确认的决定

- 运行环境：本机 Windows Codex；先作为个人插件开发和验证。
- 设备范围：保留现有幻尔小车（`hiwonder`）与通用 MicroPython ESP32（`generic`），包括现有四足机器人预设。
- 交互：首版只提供对话中的 MCP 工具；不移植 DSH 悬浮面板。
- 策略：沿用现有 `auto`、`confirm-write`、`confirm-all` 三档语义。默认 `confirm-write`，使用工作区已有的 `esp32-ide/workbench-policy.json`。
- 串口：DSH 与 Codex 各自连接，必须先在一边断开才能在另一边连接；Codex 不自动抢占或关闭 DSH 连接。
- 下载备份：用户已确认，覆盖板载目标前若无法成功备份旧内容，必须中止覆盖写入。仅当能明确证明目标文件不存在时，才可把操作当作首次创建；无法区分文件不存在与读取失败时一律中止。
- 阶段 3a 代码授权：用户已明确授权实现真实桥连接、断开、停止、运行、中断及单行 REPL 工具和无硬件测试。该授权不包含连接或控制实体 ESP32；设备测试必须另行授权。
- 阶段 3b 代码授权：用户已明确授权实现工作区根目录 `.py` 下载、板载文件列表/读取/写入/删除和 PID 读取/修改，并进行无硬件测试；不得运行真实 bridge、访问串口或操作实体设备。若需兼容性修改 `../bridge.py`，只允许增量添加 Codex 严格备份能力，保持 DSH 不传 strict 参数时的默认行为；不修改 `../dsh-plugin/`。

## 首版功能

1. 识别、列出和手动认领工作区；保留已有 `board.json` 的机型、入口文件和标签语义。
2. 查询串口、连接状态和设备信息；连接及断开设备。
3. 读取控制台输出，向 MicroPython REPL 发送单行命令；运行、中断和执行机型对应的停止动作。
4. 下载工作区根目录 `.py` 到机型对应的主程序入口；在覆盖前保证旧内容已成功读取、保存并校验备份；备份失败则不覆盖。继续执行大小、CRC32 和语法校验；校验失败不得报告成功。
5. 列出、读取、写入、删除板载文件；读取和修改主程序中的 Kp/Ki/Kd。
6. 对上述操作提供清晰的工具输入、结果、错误信息和超时反馈。

## 首版之外

- DSH 式常驻悬浮面板、多个客户端共享一个实时串口连接、多板并发、固件烧录或擦除、远程设备控制。
- 不改变现有 DSH 插件或当前板载程序的行为。

## 验收条件

- 无设备时可完成协议和逻辑测试，且不会误连串口或写板。
- 只读工具能返回结构化状态；设备不在或串口被占用时明确报错。
- `hiwonder` 和 `generic` 的入口文件、串口选择和停止语义与现有桥一致。
- 三档策略分别覆盖运行/REPL 等操作与写板/删文件/PID 修改；确认要求不能只靠模型自行传入 `confirmed:true` 绕过。
- 用户确认必须来自经验证的 MCP 人类交互通道；拒绝、取消、通道不支持或无法确认来源时，受策略保护的动作必须 fail-closed。模型提供的 `confirmed`、token、nonce 不能充当用户批准。
- DSH 占用串口时 Codex 不自动断开它；Codex 退出后释放自己持有的串口。
- 使用测试设备完成一次经用户明确授权的只读联调后，再单独批准任何写板试验。
