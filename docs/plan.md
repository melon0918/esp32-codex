- 范围：个人安装器新增 `-McpHost Wsl`，仅将 MCP 的 command/cwd 用默认发行版 wslpath 转成 Linux 路径；cmd.exe 的 Windows launcher 参数、Windows Python、Bridge 与 COM4 归属保持。原生 Windows 使用默认 `-McpHost Windows`。
- 退出标准：启动/打包回归及 PowerShell 解析通过；WSL 中使用最终缓存配置完成 MCP initialize/tools/list。设备行为不是此修复的验收对象。

UI-11 结果：上述退出标准已通过；安装版本 0.2.0+codex.20260928030205，WSL 使用最终缓存 MCP 配置发现 26 工具，无设备工具调用。当前对话工具重新挂载仍待客户端完成。

- 范围：仅当 MCP 与面板都使用真实 bridge 时，将 mock-only 的 `mock_scenario` 从活动租约身份比较中排除；真实桥开关、脚本等运行配置仍须匹配，mock 模式场景隔离不变。
- 退出标准：MCP `readonly` 与面板 `fileops` 配置可共享一个 broker lease；有实际权限差异时仍拒绝加入；项目源与当前 Windows 运行源的回归测试通过；面板重新读取有效快照。串口保持断开，不读写设备。
- 结果：项目源 broker 回归 24/24、当前 Windows 运行源 broker 回归 29/29 通过；修复已同步至发行包和正在使用的 Windows 插件源。独立 API 快照有效，但当时没有点击真实窗口；“连接按钮前端条件已满足”的推断后来被 RCT-01 实际窗口观察推翻。UI-12 的 broker 修复仍有效，按钮异常另由 RCT-01 修复。

## UI-13：面板控制操作结果提示（2026-09-28）
- 目标：修复 Web 面板把桥/Broker 传输不确定结果改写成普通失败的问题，防止用户据此直接重放可能已执行的控制命令。
- 范围：面板控制 API 的异常结果映射、与 MCP 共用的不确定结果识别函数、项目发行包同步及无硬件回归测试；不改变操作门禁或确认流程，不连接串口、不操作设备。
- 验收标准：已知超时/传输失败返回“结果未知，先刷新状态，不要重放”的安全提示；普通预检/拒绝错误不误标为结果未知；错误输出不泄露异常全文；相关测试通过。
- 结果：共享分类器由 MCP 与面板共同使用；面板对结果未知的异常显示“先刷新状态，不要重放”，普通异常保持通用提示。源目录和自包含发行包的控制/确认定向测试各 23/23 通过；发行包已重建并校验关键文件同步。未连接串口或操作设备。

## UI-14：COM4 连接错误回传（2026-09-29）
- 范围：修正控制 RPC 管道默认 15 秒等待与桥 `connect` 超时相同的问题，并给连接命令覆盖其板端探测和清理的时间预算；不改变设备命令或确认策略。
- 退出标准：控制 RPC 等待长于桥命令预算；定向测试通过；在当前真实 COM4 上单次连接失败能够返回底层错误，随后状态确认为断开。板端无 REPL 回应时保留硬件/固件原因未定的结论。
- 结果：控制 RPC 使用桥命令预算加 15 秒，`connect` 桥预算延至 30 秒；定向测试通过。重载 broker 后，COM4 约 16 秒返回明确的板端无响应/回显不完整错误，随后 `connected=false`。独立 pyserial 可打开 COM4，但发送中断后 4 秒无输入字节；USB 串口枚举与端口打开正常，ESP32 固件/供电/UART 链路的具体故障点仍需现场检查。
